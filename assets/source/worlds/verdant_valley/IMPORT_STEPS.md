# Verdant Valley base kit (30 pieces): import steps

Generated by `export_verdant_valley_kit.py` from `verdant_valley_30_base_kit.blend`
(delivered 2026-09-24 as `verdant_valley_30_5x6_arch_vine_normals_review.blend`).

## Cleanup testing branch (2026-09-27)

The reviewed, joined 30-mesh scene is `verdant_valley_30_cleanup_review.blend`.
Export it without regenerating terrain or changing the scene's `chunk_*` names:

```
blender -b --factory-startup assets/source/worlds/verdant_valley/verdant_valley_30_cleanup_review.blend --python assets/source/worlds/verdant_valley/export_verdant_valley_kit.py -- --joined-scene --out-fbx assets/export/worlds/verdant_valley/verdant_valley_structure.fbx
```

This validates 30 unique meshes, the `Col` corner colors against face materials,
footprints and triangle budgets, then reimports the FBX for a geometry check.
It removes the 5×6 review-grid offsets in the background export process only;
the saved Blender scene retains the layout. Import the FBX below in Studio,
select **Roblox XML Model Files (`*.rbxmx`)** for Save to File, then run
`tools/sync_asset_ids.py verdant_valley --write`. The scene's
`chunk_side_treasure_hollow` and `chunk_side_wardens_clearing` names are
preserved; the ID sync maps them to the existing CAP manifest keys.

Keep the older base source and exports until this branch has passed a Studio
walk and asset-access check in the game experience.

## 1. Import to Studio

1. Studio → **3D Importer** → `assets/export/worlds/verdant_valley/verdant_valley_structure.fbx`.
   Leave the importer's scale alone. It is one FBX with 30 objects, which comes in as one Model with 30 MeshParts.
2. Check one piece's size: each piece must read **256 wide × its height × 256 deep** (the boss is **384 × 113.7 × 256**).
   A piece reading 1000× too big means the FBX was written in millimetres (see `CHUNK_AUTHORING.md`).
3. Right-click the Model → *Save to File* →
   `assets/rbxm/chunks/verdant_valley/VV_STRUCTURE.rbxmx`.

## 2. Wire the asset ids

Write `ids.json` mapping each MeshPart name to its MeshId, for example
`{"chunk_entry_dawn_meadow": "rbxassetid://123", ...}`. Then re-run:

```
blender -b --factory-startup assets/source/worlds/verdant_valley/verdant_valley_30_base_kit.blend     --python assets/source/worlds/verdant_valley/export_verdant_valley_kit.py -- --ids ids.json
```

Copy the files it writes into `src/`:
- `generated/VerdantValley.luau` goes to `src/shared/Content/Chunks/VerdantValley.luau`
- `generated/AssetManifest_VV.luau` replaces the 30-piece VV block in `src/shared/Content/AssetManifest.luau`

Until then, every new key is `PLACEHOLDER` and `ChunkLoader` draws the labelled blockout.

## 3. Walk it

Press Play. For each piece, the Output prints `[ChunkLoader] VV_CHUNK_… faces <turn> (score N)`.
Any "no rotation puts deck under all sockets" warning means that piece's facing needs a look.
