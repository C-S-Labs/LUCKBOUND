To activate this one-chunk prototype in Studio Edit mode:

1. Import `stone_sentinels_walk_collision.fbx` with 3D Importer at scale 1.0.
   Confirm 203 MeshParts and no import errors. Keep the 202 `walk_*` parts in
   one Model named `VV_STONE_SENTINELS_COLLISION`.
2. Select the imported `CollisionOrigin` part as the model's `PrimaryPart`.
   Move the model to the world origin with `PivotTo(CFrame.new())`, clear
   `PrimaryPart`, remove the marker, and set `WorldPivot = CFrame.new()` so the saved pivot is the Blender chunk
   walk-plane origin. Confirm the walk tiles span roughly X/Z -128..128.
3. Set all walk parts anchored, colliding, queryable, and
   `CollisionFidelity = PreciseConvexDecomposition`. Save the model to
   `assets/rbxm/chunks/verdant_valley/VV_STONE_SENTINELS_COLLISION.rbxmx`.
   Rojo places it under `ServerStorage.LuckboundChunkKits`; the loader looks up
   that exact model name. Do not replace `VV_STRUCTURE.rbxmx`.
4. Run the generated `StoneSentinelsValidation.luau` in Studio Edit mode. It
   clones the imported model at all four quarter turns, raycasts against the
   collider only, and reports misses, hits over 1 stud from the Blender
   reference, and maximum height error. Inspect the north approach in
   Collision Fidelity visualization and walk `/roll VERDANT_VALLEY test`.
   Once the model is present, `ChunkLoader` disables collision and queries on
   the joined Stone Sentinels visual mesh, and exposes translucent collider
   parts in Studio. Verify its chunk folder has `WalkCollisionPieces = 202`.

The loader keeps visual collision if the imported model is absent or empty;
the custom collider cannot be claimed as validated until the import, raycast,
and character walk pass. Keep older assets until then.
